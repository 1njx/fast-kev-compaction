# Claude Code hooks

The plugin uses Claude Code function hooks to replace a compaction with the original messages, minus the tool
calls and tool results Kev judged no longer needed. `hooks/fast-kev.ts` is a thin adapter: it reads the plugin
options, hands `session.compact` transcripts to the library in `src/` (the plugin folder is the repository root,
so the hook imports it directly) and maps the result back onto session messages. User and assistant text is
never touched.

Kev is sent the whole conversation as `state` (tool outputs replaced by a one-line note) and, for every tool call
outside the pinned first and newest messages, two questions: should the call stay, and should its full output
stay. An item is kept when Kev's probability reaches `keepThreshold`. A dropped result is truncated to its first
`truncateHeadChars` characters plus a one-line note, and a dropped call disappears with its result. How the state
is fitted into the token budget: [docs/HOW_IT_WORKS.md](../docs/HOW_IT_WORKS.md).

Function hooks are an early-access Claude Code feature. The checked-in type reference was generated by Claude
Code **2.1.274**. Turn them on with `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` (for example in `~/.claude/settings.json`
under `env`) before installing or loading the plugin. Setup: [docs/MANUAL_SETUP.md](../docs/MANUAL_SETUP.md).

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Options

The plugin declares these `userConfig` values in `.claude-plugin/plugin.json`:

| Option | Default | Notes |
| --- | --- | --- |
| `baseUrl` | none, required | Full URL of your Kev endpoint, `https://<workspace>--kev-api.modal.run/v1/systemone` |
| `apiKey` | `KEV_API_KEY` env | Bearer key of your endpoint (sensitive) |
| `model` | `kev-latest` | |
| `keepThreshold` | `0.5` | |
| `preserveRecentMessages` | `6` | |
| `compactAtPercent` | `0` (off) | Context percentage that starts an automatic compaction; 0 turns it off |
| `minReductionRatio` | `0.25` | Below this the normal summary is used instead |
| `maxStateTokens` | `25000` | |
| `maxRequestTokens` | `30000` | |
| `truncateHeadChars` | `300` | |
| `logDecisions` | `false` | Print every call's keep and drop probabilities to the chat (pages of output on a long session) |
| `requestConcurrency` | `1` | Requests in flight at once; 1 is the safest for very long chats |

Every option except `apiKey`, `baseUrl`, `compactAtPercent`, `minReductionRatio` and `model` is passed straight to
the library; see [docs/LIBRARY.md](../docs/LIBRARY.md).

## How `/kevcompact` runs

- A hook may run only about 10 s and a cold GPU needs minutes, so `/kevcompact` returns at once. A detached step
  wakes the server (`GET /v1/models`, retried) and narrates progress with toasts.
- In the interactive CLI the plugin then calls `$.session.compact()`.
- In the desktop app and headless (`claude -p`) sessions that call is unavailable, so the plugin runs the built-in
  `/compact` instead. The `session.compact` hook scores that one run with Kev (armed for 60 s, the server's idle
  shutdown). Any other manual `/compact` and every subagent compaction stay on the built-in summary.
- If `compactAtPercent` is above 0, the `turn.complete` hook starts the same flow when `context.percent` reaches it,
  with an in-flight guard and a 10-minute cooldown. The toasts say the compaction is automatic. It is off by default.
- If Kev fails, the response is malformed, the key is missing, the history cannot be fitted into the state budget
  or the reduction is below `minReductionRatio`, the hook logs a fallback and Claude Code's built-in compaction runs.
  The outcome is shown as a toast and logged, with a per-call `decisions:` line for diagnosis.
- Each cold start costs roughly $0.25 to $0.40 of GPU time. Set a $0 spend limit in Modal.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases. This plugin uses the generated
declarations from 2.1.274 in `types/claude-code.d.ts`; regenerate and review that file after a Claude Code upgrade.
